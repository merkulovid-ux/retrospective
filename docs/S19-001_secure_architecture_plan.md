# План и образ результата для задачи S19-001 (v2)

### Задача: Спроектировать архитектуру для безопасного ИИ-виджета

---

### Участвующие роли:
*   **Tech Lead (TL):** Проектирует архитектуру.
*   **DevOps Engineer:** Оценивает платформу для развертывания серверного компонента.

---

### Что будет сделано (Новый план):

Проблема обхода защиты через перезагрузку решается только на стороне сервера. Я предлагаю следующую архитектуру:

1.  **Frontend (JavaScript в виджете):**
    *   При клике на кнопку "Анализ с ИИ" frontend получает от Google **токен reCAPTCHA v3** (это происходит в фоне, незаметно для пользователя).
    *   Frontend **не обращается к API LLM напрямую**. Вместо этого он отправляет текст пользователя и токен reCAPTCHA на наш собственный бэкенд-эндпоинт.

2.  **Backend (Serverless-функция):**
    *   Мы создадим простую serverless-функцию (на платформе типа Vercel, Netlify или Yandex Cloud), которая будет служить нашим бэкендом-посредником.
    *   **Шаг 1: Rate Limiting.** Функция применяет **rate limit по IP-адресу** (например, не более 5 запросов в час с одного IP). Это решает проблему с перезагрузкой страницы.
    *   **Шаг 2: Верификация reCAPTCHA.** Если лимит не превышен, функция отправляет токен reCAPTCHA в Google для проверки. Если Google считает, что это бот, запрос отклоняется.
    *   **Шаг 3: Запрос к LLM.** Только если обе проверки пройдены, наша функция обращается к API LLM (Gemini), передавая ему текст пользователя.
    *   **Шаг 4: Ответ.** Функция получает ответ от LLM и возвращает его на frontend.

---

### Образ результата:

Мы получим **надежную, серверную защиту** для нашего ИИ-виджета. Пользователи (или боты) **не смогут обойти ограничения** простой перезагрузкой страницы, так как лимит будет привязан к их IP-адресу. API нашего LLM будет защищен от ботов и флуда, что гарантирует стабильность работы функции и контроль над расходами. При этом для легитимных пользователей процесс останется почти незаметным (благодаря невидимой reCAPTCHA v3).
